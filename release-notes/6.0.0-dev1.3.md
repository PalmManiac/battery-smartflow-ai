# V6.0.0-dev1.3: Coordinator stays available after rejected control writes

This dev1.03 test build keeps fresh coordinator measurements available when a normal regulation write is rejected by Home Assistant. The failed command remains marked as failed and is retried by the normal regulation cycle. The log now identifies whether the AC-mode, input-limit, or output-limit write was rejected.

## External field tests requested

- Upgrade from dev1.2 to dev1.3 and confirm the portal and coordinator-backed sensors remain available during normal regulation.
- If a control write is rejected during ordinary use, confirm the coordinator data remains available and the log identifies the failed write type.
- Confirm normal charge and discharge commands still work when Home Assistant accepts the service calls.
- Report the BSFAI and Home Assistant versions, selected control path, approximate local time, and a sanitized log excerpt if a write failure occurs.

Do not deliberately invalidate an entity or service target to trigger a failure. A rejected write is still a failed control command; do not publish credentials, App-Tokens, or private system details with reports.
