# More responsive regulation with clearer insights and control

This first public beta brings together the V5.2 regulation, training, dashboard, and communication-path improvements for wider real-world testing.

## Regulation and telemetry

- Poll configured Shelly grid meters independently at one-second intervals and react to fresh grid readings without waiting for the regular coordinator cycle.
- Smooth ordinary corrections near the target and use bounded faster responses for larger deviations, while respecting device power limits and higher-priority protections.
- Keep an active automatic discharge briefly through short grid-sensor gaps and exclude unavailable readings from regulation history; expire stale Zendure protection snapshots.
- Stop the unused Zendure Cloud MQTT path when ZenSDK is selected and improve reliability diagnostics for Cloud MQTT subscriptions.

## Training and dashboard

- Run passive regulation training for up to 24 hours, capture charging and discharging separately, and review sample coverage, confidence, estimated error, and overshoot before activating a candidate.
- Keep learned candidates inactive unless explicitly applied; limit them to the device and communication path used for training. Recovered, interrupted training cannot be applied as a complete candidate.
- Start and stop training and debug recordings from the dashboard, review training comparisons, and open general and expert settings there while retaining the existing Home Assistant configuration flow.
- Show hardware topology with device-specific product images, translated communication and status labels, animated battery state-of-charge flow, and clearer sensor feedback.

## Shelly and Zendure communication

- Select local HTTP or Modbus TCP for the Shelly Pro 3EM Gen2. Modbus reports total active power and signed readings for phases A, B, and C; Modbus must be enabled on the Shelly first. The classic Shelly 3EM Gen1 continues to use its local HTTP path.
- Add model-specific Cloud MQTT control for Hyper 2000 and HUB 2000 while leaving the ZenSDK path unchanged.

This is a beta release. Please monitor regulation after updating and validate newly selected communication paths with your hardware before relying on them unattended.
