# V6.0.0-dev1.9: Remove legacy battery entity controls

This test build removes the V5 Home Assistant entity control path from V6. New setups start with native Zendure discovery. Existing V5 entries become read-only until they are converted through Reconfigure. The guided conversion keeps the same config entry and its saved runtime state, preserves price, PV, grid, Shelly, and strategy settings, and removes obsolete battery entity IDs after native discovery succeeds.

## External field tests requested

- On a fresh setup, confirm setup begins with Zendure App Token discovery and no longer offers the old Home Assistant battery-entity setup.
- Upgrade an existing V5 entry. Confirm BSFAI shows the V6 reconfiguration notice and does not send `number.set_value` or legacy `select.select_option` commands before conversion.
- Reconfigure the existing entry with the Zendure App Token. Confirm it remains the same config entry, completes native discovery, and retains configured price, PV, grid, Shelly, and strategy settings.
- Check that learned regulation, training, and economic history remain available after conversion. Confirm obsolete battery control entity IDs and external battery telemetry selectors are removed from the converted entry.
- With native control disabled, confirm the integration remains read-only and never falls back to Home Assistant entity control. With native control enabled, confirm commands follow the native device path.
- Report successful and failed cases with the V6 version, screenshots, and diagnostics. Remove credentials, App-Tokens, and private system details from logs.

We will review external reports before starting another issue or development stage.
