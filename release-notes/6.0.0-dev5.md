# V6.0.0-dev5 – Explainable shadow allocation across battery groups

## Changes

- BSFAI now calculates a staged per-device allocation proposal for the active battery group from the existing regulation intent.
- The proposal prefers one lead system up to 75% of its available model limit, then uses other eligible systems, and only uses the remaining capacity in a second pass.
- Device availability, setup state, support status, HEMS blocking, protection state, SoC reserve and maximum SoC are reflected in eligibility.
- Configured circuit and upstream circuit limits are included in the proposal.
- The portal shows each proposed device power and the reason for its allocation or exclusion. The `Schattenverteilung` sensor exposes the same details for diagnostics.
- The proposal is read-only. It does not send additional commands or change the existing single-system regulation.

## Please test

- Multi-system users: check installations with 2, 3 and 4 or more configured systems, including groups with different models and capacities.
- Observe both charge and discharge situations with changing household load and PV power. Compare the group target with the per-system proposals and check that the lead choice is understandable.
- Check groups containing an offline, unsupported, incompletely configured or HEMS-blocked system, and systems at their configured SoC reserve or maximum.
- If circuit limits are configured, check that the proposal respects both each circuit and any shared upstream circuit limit.
- Confirm that existing device control and its commands behave exactly as before; this release only displays a shadow proposal.
- Please share the number of systems, their models, relevant circuit limits, screenshots of the portal proposal, and a BSFAI Debug export if an allocation is missing, exceeds a limit or is hard to explain.

Installations with one system can confirm that no extra writes occur, but cannot validate multi-system allocation behavior.
