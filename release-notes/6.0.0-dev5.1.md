# V6.0.0-dev5.1 – Smoother discharge near the minimum SoC

## Changes

- SolarFlow 2400 Pro in Autarky mode now ramps the available discharge power up gradually after the configured SoC minimum resume threshold is reached.
- The existing SoC minimum block remains in place. The taper only limits the maximum discharge power during the configured model-specific recovery range; once above that range, the normal output limit applies.
- Diagnostic attributes expose whether the taper is active, its SoC range, and its current output cap.
- Other device profiles and regulation modes are unchanged.

## Please test

- With a SolarFlow 2400 Pro in Autarky mode, observe behavior around the configured SoC minimum and its resume threshold. Confirm that discharge output rises gradually instead of jumping directly to the full house-load target.
- Observe the transition while PV is available and household load changes. Check whether the repeated transition between PV charging and discharge near the lower SoC boundary is reduced.
- Confirm that discharge still stops at the configured minimum and that normal output capability returns above the taper range.
- Check the debug attributes `soc_min_discharge_taper_active`, `soc_min_discharge_taper_start_soc_pct`, `soc_min_discharge_taper_end_soc_pct`, and `soc_min_discharge_taper_max_output_w` against the observed output.
- Please share screenshots, a BSFAI debug export, model and battery-pack details, configured SoC minimum, and whether the Zendure device reports an output limit of 0 W or a `readback_mismatch`.

The report in Discussion #909 was made on Dev4.2 and its attached file is a ZenSDK initial-sync diagnostic snapshot, not a time-correlated event log. This release tests the suspected SoC-boundary control behavior and adds diagnostics to verify it in the field.
