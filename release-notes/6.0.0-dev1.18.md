# Keep Hyper pack telemetry visible during sparse updates

This test build fixes pack sensor matching in the hardware portal and avoids stopping regulation solely because individual pack SoC updates have aged out while the aggregate system SoC is still fresh. Confirmed pack inventory and known pack profiles are still required for capacity calculations.

## External field tests requested

- Confirm that each Hyper battery pack now shows its available telemetry in the portal, including SoC, power, voltage, and temperature where supported. Check whether the per-pack flow animation follows charging or discharging.
- During a longer regulation period, observe whether control remains active when pack-level SoC updates are sparse but the system remains online and its aggregate SoC is current.
- Check that regulation still stops safely if the system SoC becomes unavailable or the pack inventory/profile is incomplete.
- If telemetry is missing or regulation stops, capture the approximate local time, portal values, and a debug recording covering the event. Include BSFAI and Home Assistant versions, and remove App Tokens, serial numbers, network addresses, and other private identifiers.

We will review external reports for this dev1 test build before advancing to the next development issue.
