# V6.0.0-dev1.8: Economic discharge remains available during learned charge planning

This dev1.8 test build includes PR #844. Economic discharge now uses the stored battery charge cost when the legacy trade average is unavailable. This keeps the discharge decision aligned with the effective threshold shown by the integration while retaining the existing Automatic-mode, SoC, price, and protection checks.

## External field tests requested

- In Automatic mode, with a learned charge plan waiting and the battery SoC above its configured minimum, check whether the system discharges when the current import price is above the displayed effective discharge threshold.
- Check whether discharge stops or changes back to the planned charging behavior after the price falls below the effective threshold.
- Report any case where the displayed price is above the threshold but battery output remains at 0 W, or where discharge continues below the threshold. Include timestamps, screenshots of the price and threshold, battery SoC and minimum SoC, and diagnostics that show the learned plan and selected strategy.
- Avoid forcing a battery into unsafe conditions. Include the BSFAI version and remove credentials, App-Tokens, and private system details from logs.

Please report both successful and failed cases in the V6 test discussion. We will review field results before starting another issue or development stage.
