# V6.0.0-dev5.3 – Validate device response before proposing trained gains

## Changes

- Require the measured 95th-percentile device response delay to fit within the median training sample interval before proposing a gain change.
- If the device response is too slow or cannot be measured reliably, keep the device profile unchanged instead of proposing gains from samples that may still reflect an older command.
- Bump the integration version to `6.0.0-dev5.3`.

## Please test

- Update and reload the integration, then run regulation training during normal PV charging and/or discharge operation.
- Check whether training proposes a gain only when it has enough repeated response data and the measured response delay fits within the sample interval.
- If the response is delayed, confirm the evaluation reports insufficient dynamic-response data and leaves the existing profile unchanged.
- Compare the proposed result with the Standard profile, especially import/export overshoot, response time, and whether regulation is interrupted.
- Please report the installed version, training evaluation details, a Debug export covering the training period, and the device model plus selected control transport.
